# 실기 기준 맵·지형 정보·costmap과 경기 STL 기반 위치 보정 — 단계 계획표

작성일: 2026-10-13. 이 문서는 단계별 목표와 검증 조건을 정하는 로드맵이다. 코드별 상세 구현 계획이나 구현 완료 보고서는 아니다.

2026-10-14 갱신: 현재는 **1단계의 영상 기록·재생과 2단계의 실기 3D 생성 경로를 확보하고, 기준 맵의 정확도·연속성을 검증하는 중**이다. IMU·encoder 기록/융합과 실측 정확도는 미완료이므로 1~2단계 전체를 통과했다고 표시하지 않는다. 3~4단계의 기반 코드를 선행 구현했고, 8단계 중 실시간 촬영 안내만 먼저 추가했다. [현재 화면·지도 보기](mapping-viewer.md).

## 목적과 공통 구조

경기는 다른 경기장에서 진행되며 3D 사전 맵인 STL이 제공된다. 지금 실기 장소에는 그런 맵이 없으므로, 먼저 D435로 실기 장소를 촬영해 기준 3D 맵을 만든다. 별도 주행에서는 이 맵을 경기 STL처럼 사용해 위치·방향의 누적오차 보정을 시험한다. 형상에서 높이·경사·거칠기·단차·관측 신뢰도를 추출하고, 로버 조건에 따른 costmap을 만들어 향후 달탐사 로봇의 경로·주행 판단에 도움이 되는 지형 정보를 축적하는 것이 목표다.

- Pi는 영상·센서 수집과 전달을 담당하고, 원본과 결과는 노트북에 저장한다.
- 기준 맵 제작의 SLAM·정합·최적화·TSDF는 노트북에서 계산하는 것을 목표로 한다. 실시간 처리보다 지도 품질을 우선한다.
- 현재 앱 기본값은 Pi sensors-only 전송 → 노트북 원본 저장·live ORB 촬영 안내 → 종료 후 전체 원본 ORB·TSDF다. 기존 Pi ORB 선택 모드도 유지한다. 실시간 안내 화면은 초기 optical X-Z 잠정 관측 투영이며 지형/costmap·맵 보정을 완료한 것으로 표시하지 않는다.
- 기준 맵 제작에는 D435 depth를 활용한다. 보정 주행의 센서 구성은 경기에서 사용할 조건에 맞춘다. depth로 보정하는 실험을 추가하더라도 별도 결과로 구분한다.
- 손으로 들고 촬영할 때는 카메라만으로 시작한다. 로버 장착 후 사용 가능한 IMU·encoder를 시각·좌표계 검증과 함께 추가한다.
- 기준 맵 촬영 A와 보정 평가 주행 B를 분리한다. B에서는 A의 기준 맵을 고정하고 갱신하지 않는다.
- 위치 정합용 고정 기준 맵과, 새 관측으로 갱신하는 현장 지형·주행 경험 층은 별도로 보존한다.
- ORB-SLAM3 기반 궤적 추정 + D435 depth의 TSDF 융합을 기준 맵 제작의 기본 방식으로 정했다. 추가 depth 정합/궤적 최적화의 세부 방법·채택 기준과 ORB-LINE의 대체 여부는 비교 시험으로 결정한다. COLMAP은 촬영 후 pose/형상 비교 후보이며 아직 실행·통합하지 않았다.

```text
촬영 A → 노트북 궤적 최적화 → TSDF/mesh → 품질 검사 → 고정 기준 맵
                                                        ├→ 지형 정보 층 → 로버별 costmap
                                                        ↓
별도 주행 B → 이동 추정 → 현재 관측과 기준 형상 정합 → 누적오차 보정
                                                        ↑
경기에서는 제공 STL을 같은 기준 형상 입력으로 사용

별도 주행 B의 새 표면 관측·주행 경험 → 현장 갱신 층 → costmap 재계산
```

## 단계별 검증의 핵심

### 1~2단계: 기준 맵을 믿을 수 있게 만들기

- 원본·보정값·시각을 함께 보존해 같은 입력으로 반복 계산한다. SSH 수신 시각을 촬영 시각 대신 쓰지 않는다.
- IMU와 카메라의 clock 관계, 축과 extrinsic을 확인한다. encoder는 미끄러짐이 있으므로 절대 정답으로 쓰지 않는다.
- 첫 촬영은 작은 구역에서 시야를 겹치며 시작점으로 돌아온다. 손 촬영에는 encoder가 없어도 된다.
- 현재 TSDF는 입력받은 최종 ORB keyframe pose를 융합한다. TSDF 자체가 궤적 누적오차를 해결한다고 해석하지 않는다.
- 분리된 ORB map은 좌표가 다르므로 임의 병합하지 않는다. 정합 근거가 없으면 별도 결과로 남기고 기준 맵으로 채택하지 않는다.
- 점 ORB로 먼저 기준 맵을 만든다. 점선·CLAHE는 같은 기록의 개선 효과가 확인될 때 채택하며 기본 시험의 필수 조건으로 삼지 않는다.
- 실제 측정 가능한 거리·높이·시작 위치를 기록한다. voxel 크기는 정확도 보증이 아니다.

### 3~4단계: 지형 정보를 보존하고 로버별로 해석하기

- 3D mesh는 원본 형상, 2.5D 지형 지도는 분석용 층, costmap은 특정 로버의 주행 판단용 결과로 보존한다. 색칠한 단일 costmap만 남기지 않는다.
- 지형 층에는 높이(m), 법선/경사(deg)와 방향, 국소 평면 대비 거칠기(m), 주변 단차(m), 장애물, 관측 여부/시각/개수와 품질 지표를 저장한다. 거칠기 계산의 공간 범위도 기록한다.
- depth·pose 오차의 불확실성 모델이 검증되기 전에는 관측 개수나 정합 잔차를 보정된 확률·covariance처럼 표시하지 않는다.
- 격자 해상도는 실제 관측 해상도·노이즈와 바퀴/차체 규모에 맞춰 결정한다. 노이즈를 거친 지형으로 오인하거나 평활화로 작은 장애물을 지우지 않는지 검사한다.
- 2.5D로 표현하기 어려운 벽·돌출부·겹치는 표면은 3D 원본과 장애물 층에 보존한다. 맵의 구멍을 채운 추정 영역과 실제 관측 영역을 구분한다.
- costmap은 지형 층과 로버 제원/설정을 함께 입력받는다. 통과 불가 조건은 큰 비용과 구분하고, unknown을 안전한 평지로 취급하지 않는다.
- 초기에는 경사·거칠기·단차·장애물 여유와 관측 품질로 비용을 구성한다. 진행 방향별 경사 위험은 방향 정보를 보존해 이후 반영할 수 있게 한다.
- 마찰·지지력·침하·소비 에너지는 영상 형상만으로 실측한 값이 아니다. 추후 주행으로 얻은 슬립, 조건별 흔들림, 직접 계측 가능한 소비 에너지 등을 별도 경험 층에 추가한다.
- 슬립 평가에는 encoder와 독립적인 이동 추정이 필요하다. 주행 방향·속도·하중·추정 품질과 함께 저장하고, 관측하지 않은 셀의 슬립을 0으로 채우지 않는다.

### 5~6단계: 경기 STL에도 적용되는 보정 만들기

- 촬영 mesh와 STL의 공통점인 형상을 사용한다. ORB Atlas 재지역화는 보조 비교로 둘 수 있지만 STL 형상 보정의 대체 검증으로 삼지 않는다.
- 스캔의 거친 표면이나 STL의 삼각분할 경계를 모두 실제 구조선으로 취급하지 않는다.
- 첫 버전은 알려진 시작 위치·방향으로 정렬한다. 시작 위치를 전혀 모르는 전역 재지역화는 첫 보정 성공 이후 별도 범위로 다룬다.
- 평평한 바닥이나 반복 구조처럼 위치를 구분하기 어려운 관측에서는 확인 가능한 방향만 보정하거나 정합을 거부한다.
- 스캔 맵 제작에 쓴 depth와 주행 중 보정에 쓰는 관측을 구분한다. 경기 센서 조건에서 얻는 관측으로 보정이 되는지 확인한다.
- 보정은 이동 추정과 별도 기록해 지도 좌표의 위치 변화와 연속적인 로컬 이동을 구분한다. IMU를 중복해서 독립 관측으로 융합하지 않는다.

### 7~9단계: 효과와 운용 조건 확인

- B의 OFF/ON 비교는 같은 입력·시작 정렬·센서 조건을 사용한다. 각 궤적을 따로 정답에 맞춰 오차를 숨기지 않는다.
- 기록 기반 시험이라도 B의 미래 프레임이나 종료 후 최적화 위치를 주행 중 보정 입력으로 쓰지 않는다.
- 직접 만든 맵은 GT가 아니다. 맵 일치도와 독립 실측 기준 오차를 따로 보고한다.
- 기준 맵이 없는 영역과 STL/현장 불일치 구간에서는 잘못된 형상에 강제로 맞추지 않는다.
- 노트북에서 보정 계산을 할 수 있다. 경기 중 노트북/통신 사용 가능 여부가 확정되면 동일 계산을 유지할지 배치만 조정할지 결정한다.
- 제어 코드를 변경하는 경우 먼저 시뮬레이션/fake 통신 검증을 하고, 이후 바퀴를 띄우거나 저속으로 실기 검증한다.

## 장비 없이 준비할 수 있는 작업

2026-10-13 사전 구현: [Pi sensors-only·노트북 재생·지형/costmap 코드와 메모리 범위](laptop-terrain-preparation.md). 실제 실기 통과 체크는 아래 목록과 구분한다.

- 알려진 평면·경사·단차·장애물·미관측 구역으로 3~4단계의 지형 정보와 비용 산출 시험을 준비한다.
- 기존 기록·합성 형상으로 5단계의 단위/축/정합 시험을 준비한다.
- 기존 시뮬레이션 기록으로 6단계의 보정 진단과 실패 거부 동작을 준비한다. 이를 실기 성능으로 표시하지 않는다.
- 노트북 중심 수집/재생 경로의 상세 설계를 정리한다. 실제 전송 부하와 센서 동기화 통과 여부는 장비 연결 후 판단한다.

## 범위와 근거

이번 로드맵의 중심은 기준 맵 제작·위치 보정·지형 정보·로버별 costmap이다. 지형 데이터와 주행 경험을 재사용해 향후 탐사 로봇이 위험 구간을 판단하는 데 도움이 되도록 한다. 자율 주행 전체·브러시 임무·AI HAT 적용·모터 제어 변경은 완료 조건에 포함하지 않는다. 지구 실기 결과를 실제 달 표토 물성이나 달 환경 성능으로 표시하지 않는다.

기존 STL 융합 실험에는 벽 방향을 이용한 yaw 보정과 시뮬레이션 입력에 대한 제한이 있으며, 일반 mesh를 이용한 절대 위치 보정 전체가 완료된 상태는 아니다.

- [현재 구현과 실기 검증 범위 (별도 자료)](../data-assets.md)
- [기존 매핑 앱의 데이터·저장 구조](handheld-mapping-app.md)
- [기존 STL 융합 실험 (별도 자료)](../data-assets.md)
- [기존 지형·슬립 지도 연구 설계 (별도 자료)](../data-assets.md) — 현재 위치 추정 구현은 ORB-SLAM3이며 이 과거 설계의 OpenVINS 제안과 구분한다.
- [grid_map 공식 저장소](https://github.com/ANYbotics/grid_map) — 여러 지형 층의 보존, 법선·거칠기·주행성 계산과 비용 지도 변환의 참고. 라이브러리 채택과 설치를 확정한 것은 아니다.
- [elevation_mapping 공식 저장소](https://github.com/leggedrobotics/elevation_mapping) — 로봇 위치 불확실성을 고려한 높이 지도 구성의 참고. 현재 앱에 통합된 상태는 아니다.
